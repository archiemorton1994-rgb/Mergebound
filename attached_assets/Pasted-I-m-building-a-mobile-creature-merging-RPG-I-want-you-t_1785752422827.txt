Non-negotiable architecture rule

Game logic must be completely separate from UI.

src/game/ — pure TypeScript functions. Merge rules, stat generation, save/load serialisation. These files must not import anything from React, React Native, or any UI library. They take data in and return data out.
src/screens/ — the React Native screens and components. These call into src/game/ but contain no game rules of their own.
src/data/ — content as JSON: type definitions, species list, tier settings, balance numbers. No hardcoded game values inside logic or UI files.

This matters a lot to me. If a rule or a number ends up hardcoded inside a screen component, that's a bug.

Game data model

Creature

name

Types — 8 total, defined in data, easily renamed later.

Six core types in a weakness ring, where each is strong against the next and weak to the one before it:

Ember → Bloom → Tide → Gale → Crag → Volt → Ember

Two rare types, Umbra and Lumen, which are strong against each other only and neutral against everything else.

Store this as a data table, not as if/else logic.

Merge rules

merge(creatureA, creatureB) → newCreature. Implement exactly this:

Tier

If both parents are the same tier T, result is tier T + 1
If parents are different tiers, result is the higher of the two tiers (no increase)

Types

Take the higher-tier parent's types first, then the other parent's types
Remove duplicates
Take the first two only. A creature can never have more than two types

Stats

Base = the average of the two parents' stats, per stat
Multiply by the tier multiplier from the data file
Apply a random roll of ±15% per stat, rounded to integers

Species — inherit from the higher-tier parent. On a tie, pick either deterministically.

Consumption — both parent creatures are removed from the collection; the result is added.

Merging must be a pure function with no side effects. Write it so the same inputs always produce the same outputs given a seeded random source.
